# 三小时维护窗口目标模式

日期：2026-11-25  
项目：`flowli-blog`  
窗口：3 小时，分 6 个 30 分钟时间盒。时间盒是顺序执行的，但允许在检查失败时暂停推进、先修根因。

## 总目标

把一个已经成熟但刚经历过多次交互修补的博客前端，收束到“**语义正确、交互稳定、视觉克制、检查可复现、维护记录可追溯**”的状态。这个窗口不是重写，不追求大量视觉变化，而是降低后续维护成本和回归风险。

## 非目标

- 不重写 CSS 架构；现有 `foundation/tokens/materials/layout/components/motion` 分层保持。
- 不改内容模型、页面路由、文章数据、字体子集策略。
- 不为了“更漂亮”临时添加渐变、卡片、色条、阴影或动效。
- 不用刷新视觉基线来掩盖布局回归；只有确认是有意视觉变化时才刷新。
- 不在未验证的情况下把“看起来应该没问题”当作完成。

## 阶段计划

### H1 · 基线锁定（30 分钟）

目标：把当前工作区从“连续修补后的未提交状态”恢复到可验证状态。

动作：
- 盘点未提交改动，确认每个改动对应一个已发现问题。
- 跑 `css:check`、`type-check`、`check`、`check-stylus`、`build`、`visual:check`。
- 对失败项先判断是否是可接受视觉变化；否则修根因。

退出条件：所有检查通过，工作区改动有明确归属，没有“不知道为什么改了”的文件。

### H2 · 语义与可访问性（30 分钟）

目标：修复可点击元素的语义错误，并确保键盘可见。

范围：
- 分类、标签、侧栏链接、按钮、下拉项。
- 禁止 `<a>` 包 `<button>` 或可点击 `div` 冒充链接。
- 所有可点行有明确 `href`、可读名称、手型和 `:focus-visible`。

验证：DOM 抽检、键盘焦点抽检、命名链接抽检、视觉回归。

退出条件：没有嵌套交互元素；目标行均为单一链接；焦点态可见；视觉无意外变化。

### H3 · 导航与滚动稳定性（30 分钟）

目标：非首页之间切换时，只让内容栏过渡，侧栏保持静止；进入详情不先回顶再切换。

范围：
- Swup hooks：`visit:start`、`content:replace`、`page:view`。
- 滚动归零时机。
- 侧栏持久化与过渡类。

验证：逐帧采样 `scrollY`、布局状态、侧栏矩形、透明度、位移；导航脚本全通过。

退出条件：滚动与布局切换同帧；侧栏位置/尺寸/透明度/位移全程不变；导航脚本 OK。

### H4 · 视觉克制与反馈统一（30 分钟）

目标：清理“AI 味”交互反馈，统一为纸张/索引语言。

范围：
- 分类/标签 hover。
- 数字读数和徽章。
- 侧栏行分割与选中反馈。
- 不使用灰圆角块、彩色左边条、过度阴影、通用 pill。

验证：真实鼠标 hover 截图；亮/暗主题对比；视觉回归。

退出条件：hover 只表达状态，不抢视觉；数字是安静读数；亮暗主题都自然。

### H5 · 响应式与工程约束（30 分钟）

目标：确保桌面/窄屏/减少动效/强制颜色下没有结构性回归，并把约束固化到校验脚本。

范围：
- 768 / 1024 / 1280 / 1440 / 1920 宽度抽检。
- `prefers-reduced-motion`、`forced-colors`。
- `css:check` 规则是否覆盖新增约束。
- 文档与实际实现是否一致。

退出条件：无横向溢出；侧栏与正文列稳定；架构检查通过；文档不过时。

### H6 · 最终回归与交接（30 分钟）

目标：全量检查，形成可交接状态。

动作：
- 完整跑一遍：架构、类型、Astro、Stylus、构建、视觉、导航、资源。
- 更新维护记录。
- 明确列出已改文件、验证结果、未提交状态。
- 除非用户明确要求，不自动推送。

退出条件：所有验证证据齐全；没有未解释的失败；工作区状态清楚。

## 每步统一门槛

任何阶段只要改了代码，必须通过：

```sh
pnpm css:check
pnpm type-check
pnpm check
pnpm check-stylus
pnpm build
pnpm visual:check
```

涉及交互时还要补运行时采样或导航脚本。失败时不得进入下一阶段。
