有天有人给我截了张图，说：这里是不是歪的？图里是导航栏右侧的四个工具图标，肉眼看，最右边那个确实比另外三个高一点点。

我的第一反应是调 `margin-top`。幸好没有。

## 先测量，别猜

我用一个脚本量了四个按钮的实际位置，结果很明确：前三个按钮的垂直中心都是 28px，第四个是 25px，差了 3px。三个对，一个错，那大概率不是整体布局问题，而是这个组件自身的结构问题。

再往下一层量，我发现第四个按钮的外层 wrapper div 也比按钮本身高 3px。按钮的盒模型没问题，是它的容器把它顶上去了。

## 凶手是 inline 的基线

行内元素会参与基线对齐。一行文字里，基线下方要给字母的降部（比如 g、y 的下伸）留出空间，这个 descender gap 会撑高行盒。当一个 inline-flex 按钮和一个空的行内盒子排在同一行，浏览器按基线对齐，视觉中心就偏了，那 3px 正是这个间隙。

我之前的样式里有一条：

```css
.site-header__tool button {
  display: inline-flex;
}
```

## 修复：让基线不参与布局

思路不是给某个按钮加 `transform: translateY(3px)` 把它按下去，那只是把症状盖住，换字体、换系统还会歪。正确做法是**消除行内基线**：

```css
.site-header__tool [data-header-trigger] {
  display: flex;
  line-height: 0;
}

.site-header__tool [data-header-trigger] svg {
  display: block;
}
```

另外，工具组件最外层的 island wrapper 也要处理成块级 flex，否则它自身仍然会产生行盒。改完之后再量一次，四个按钮的中心全部是 28px。

## 顺带修掉的一个大坑

这次改动还牵出一个更严重的问题。原来的选择器是 `.site-header__tool button`，这是一个**无边界的后代选择器**。展开的面板 DOM 也在 `.site-header__tool` 里面，所以面板里的每个语言选项、明暗选项，都被这条规则强行压成了 36x36 的方块，文字横向溢出 28 到 122px，hover 也完全失效。当时我以为那是面板样式没跟上，其实根因在这里。

修复方式是给真正的工具栏触发按钮加一个标记 `data-header-trigger`，然后所有图标按钮的尺寸规则只匹配这个属性，面板内部的元素彻底不受影响。

## 教训

- 视觉对齐问题，先量坐标，再猜原因。肉眼判断差 3px 很容易，判断为什么差 3px 很难。
- 三个对、一个错的时候，先比较那个错的结构差异，而不是去调整个容器的 padding。
- 通用后代选择器在组件化页面里非常危险，尤其是组件会展开浮层的时候。给目标加一个明确的 hook，比写复杂的选择器链省心得多。
- `line-height: 0` 加 `display: block` 是处理图标基线偏移的经典组合，但要知道它为什么有效，而不是当成咒语。
